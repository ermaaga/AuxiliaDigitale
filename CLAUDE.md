# AuxiliaDigitale (Auxilia Next)

Multi-tenant platform for clients, cases, appointments and marketing campaigns: .NET 10 REST API (`backend/`) + Next.js tenant app and platform console with BFF (`frontend/`). Rewrite of the legacy Blazor app `../Auxilia`; this repo is the monorepo the blueprint calls `auxilia-next`.

- Plan, current status and next task: `docs/PLAN.md` — read it first, update it at the end of every session.
- Decisions (override the skills marketplace docs when they conflict): `docs/decisions.md`.
- Architecture: `docs/architecture/ARCHITECTURE.md`.
- Parity contract (no legacy feature may be lost): `docs/parity/` (F01–F35) and `docs/parity/legacy-quirks.md`; new features: `docs/requirements/` (N01–N03).
- Before every task load the `auxilia-dev` skills: always `auxilia-architecture` + `auxilia-dependency-policy`; for a story `auxilia-story`; plus those listed in the task.
- Backend (.NET SDK pinned in `backend/global.json`; on this Mac the arm64 SDK is in `~/.dotnet` → `export DOTNET_ROOT=$HOME/.dotnet PATH=$HOME/.dotnet:$PATH`):
  - build: `dotnet build backend/Auxilia.slnx -c Release` (warnings are errors)
  - test (from `backend/`, where `global.json` selects Microsoft.Testing.Platform): `dotnet test --solution Auxilia.slnx -c Release --ignore-exit-code 8` (exit 8 = test project without tests; drop the flag once every project has tests)
  - coverage gate (CI, ≥ 80% lines, coverlet.MTP — ADR 0014): `dotnet test --project tests/Auxilia.Application.Tests -c Release --coverlet --coverlet-include "[Auxilia.Application]*" --coverlet-threshold 80 --coverlet-threshold-type line` (same for `Auxilia.Domain.Tests` with `[Auxilia.SharedKernel]*` + `[Auxilia.Domain]*`)
  - restore is locked (`packages.lock.json`); after changing packages run `dotnet restore backend/Auxilia.slnx --force-evaluate` and commit the lock files
  - audit: `dotnet list backend/Auxilia.slnx package --vulnerable --include-transitive`; licenses: `cd backend && dotnet tool restore && dotnet nuget-license -i Auxilia.slnx -t -a ../.github/license-allowlist.json -mapping ../.github/nuget-license-mappings.json -override ../.github/nuget-license-overrides.json`
- Local infrastructure (ADR 0013, no Aspire): `docker compose -f deploy/compose.dev.yml up -d` (Postgres, Valkey, RabbitMQ); run Api/Worker with `dotnet run --project backend/src/Auxilia.Api` / `…Auxilia.Worker`; Api and Worker need the Catalog (shared user-secrets id `auxilia-api`): `dotnet user-secrets set ConnectionStrings:Catalog "Host=localhost;Database=auxilia_catalog;Username=auxilia;Password=<dev password>" --project backend/src/Auxilia.Api`; `ConnectionStrings:Redis` (Valkey, `localhost:6379` in `appsettings.Development.json`) is optional: without it the reference-data cache is in memory only. `ConnectionStrings:RabbitMq` (user-secrets, e.g. `amqp://auxilia:<dev password>@localhost:5672`) is required by the Worker and optional for Api/auxctl (without it outbox messages stay pending). Logs: console JSON + daily files in `logs/tenants/{slug}/…` and `logs/platform/…` at the repo root (setting `AuxiliaLogging`).
- API contract: `backend/openapi/v1.json` is checked by `OpenApiContractTests`; after changing endpoints run (from `backend/`) `AUXILIA_UPDATE_CONTRACTS=1 dotnet test --project tests/Auxilia.Api.IntegrationTests -c Release`, then `pnpm --filter @auxilia/api-client generate` in `frontend/` (CI fails if either is stale). Scalar UI: `/scalar` in Development.
- `auxctl` (tenant lifecycle, migrations, manual jobs): `dotnet run --project backend/src/Auxilia.MigrationRunner -- <command>`; commands and configuration in `docs/runbooks/tenant-provisioning.md` (e.g. `migrate catalog`, `tenant provision --slug dev --name Dev`, `users reset-password --tenant dev --user <name>`); secrets are read from standard input (`AuxctlCli` input), never from the command line.
- Event codes: `backend/src/Auxilia.Diagnostics` (`EventCodes`, `Log`, `Errors`); after adding one regenerate the registry: `dotnet run --project backend/src/Auxilia.MigrationRunner -c Release -- diagnostics registry --output docs/log-event-registry.md` (a test fails if it is out of sync)
- EF Core migrations (`dotnet tool restore` installs `dotnet-ef`), from `backend/`: `dotnet ef migrations add Catalog_<Description> --project src/Auxilia.Persistence.Catalog --startup-project src/Auxilia.MigrationRunner --context CatalogDbContext --output-dir Migrations`; `Auxilia.Persistence.Tests` need Docker (Testcontainers) and fail if the model has changes without a migration (tenant migrations: `--project src/Auxilia.Persistence.Tenant --context TenantDbContext`, name `<Module>_<Description>`). `Auxilia.Infrastructure.Tests`, `Auxilia.Api.IntegrationTests` and `Auxilia.Worker.IntegrationTests` need Docker too (Valkey, Postgres, RabbitMQ).
- Modules (ARCHITECTURE §5): a module = `Application/<Module>/<Module>Module.cs` (`IModuleDescriptor`, listed in `DependencyInjection.Modules`) + an Api `IModuleEndpoints` with the same code (404 when not visible for the tenant/role); `auxctl migrate catalog` syncs `catalog.modules`.
- Async work (ARCHITECTURE §13, skill auxilia-messaging-rebus): messages in `Contracts/Messages/V<n>/<Module>/` (queue `auxilia.<module>`), produced with `IMessageOutbox` inside a write operation, handled by thin `MessageHandler<T>` subclasses in `Worker/Handlers/<Module>/`; no timers (D-15).
- Outbound messages (ARCHITECTURE §8, N03): other modules send only through `Messaging.Public.IMessageDispatcher` (template code + recipient language); channel adapters implement `IMessageChannel` in `Infrastructure/Adapters/Channels/<Provider>/`; system templates are seeded EN + IT by data-migrations.
- Authentication (skill auxilia-security): access tokens JWT ES256 from `POST /api/v1/auth/token` (client app in `X-Client-Id`/`X-Client-Secret`, registered with `auxctl clients add`), rotating refresh tokens, deny-list on the distributed cache; signing keys in `catalog.signing_keys`, JWKS at `/.well-known/jwks.json`, rotation `auxctl keys rotate` (runbook `docs/runbooks/tenant-provisioning.md`).
- Account security (F35): one `IPasswordPolicy` (settings `auth.password.*`, history in `identity.password_history`) for every password change; sign-in methods are `IAuthenticationMethod` (`GET /auth/methods`; `email-otp` behind `auth.otp.enabled`); every sign-in attempt is written to `identity.login_attempts` (`GET /identity/login-attempts`).
- Platform identity (N02, D-21/D-22): System users in the Catalog (`auxctl platform users add|reset|enable|disable|list`), console sign-in with password + TOTP on a `PlatformConsole` client (`/api/v1/platform/auth/*`), tenant-scoped platform token `POST /api/v1/platform/tenants/{slug}/token`; console endpoints `RequirePlatformUser()`, tenant technical endpoints `RequirePlatformTenant()`; platform tokens never reach business endpoints.
- Authorization (F22): permissions `<module>.<area>.<action>` declared in `<Module>Permissions` (default roles; synchronised into `identity.role_permissions` at every tenant migration); endpoints `RequirePermission(...)` (or explicit `AllowAnonymous`), Managers `IAccessGuard` + `IResourceAccessPolicy<T>`; `GET /me`, `GET /me/navigation`.
- Realtime (F16/F17): SignalR hub `/hubs/notifications` (`Infrastructure/Realtime/NotificationsHub`, Redis backplane `auxilia:signalr`), push with `Application.Abstractions.Realtime.IRealtimeNotifier` to tenant-prefixed groups (user, role, session, tenant); event names in `Contracts.Realtime.RealtimeEvents`.
- Localization (F24, skill auxilia-localization): keys and translations per tenant in schema `localization`; bundles `GET /api/v1/i18n/{lang}` (anonymous, ETag, fallback lang → tenant default → en → key); editor `/api/v1/localization/*` with a tenant-scoped platform token; server texts via `Localization.Public.ILocalizer`; new keys ship EN + IT in a data-migration with its own `DataMigrations/Localization/<key>.json` (`TranslationSeed`).
- Settings and cache (ARCHITECTURE §7): typed `SettingDefinition<T>` per module, read with `ISettingsProvider`, written with `ISettingsManager`; reference data through `IReferenceDataCache`/`ReferenceDataCache<T>`, invalidated after commit with `IOperationScope.OnCommitted`.
- Tenant settings and branding (S-02, F23): technical endpoints `/api/v1/settings` (list/set/reset, tenant-scoped platform token; every setting needs `settings.<key>.description` EN + IT, `choices:` for fixed lists) and `/api/v1/branding` (public, ETag images in `configuration.branding_assets`); the web app applies it in `app/[tenant]/layout.tsx` (`<BrandingStyle>`) with `features/branding` (`loadBranding`, `brandIdentity`, `loginBackground`) and serves images at `/api/branding/{tenant}/{asset}?v=`; console pages `/platform/tenants/{slug}/{settings,branding}`. Translation keys must not be a prefix of another key (next-intl nests them; a test fails).
- Package versions only in `backend/Directory.Packages.props` (central package management); allowlist in the `auxilia-dependency-policy` skill.
- Frontend (`frontend/`, pnpm workspace; Node 24 LTS per `.nvmrc` — on this Mac `export PATH=/opt/homebrew/opt/node@24/bin:$PATH`):
  - install: `pnpm install` · dev: `pnpm dev` · build: `pnpm build`
  - checks: `pnpm lint && pnpm typecheck && pnpm format:check && pnpm audit --audit-level moderate && pnpm licenses:check`
  - Next.js 16: read `frontend/apps/web/AGENTS.md` and the bundled docs in `node_modules/next/dist/docs/` before writing Next code.
  - shadcn components live in `frontend/packages/ui` (see its README: make imports relative after `shadcn add`).
  - tests: `pnpm test` (vitest in `packages/ui`, `packages/api-client` and `apps/web`). API mocks in Vitest with MSW: `useMsw()` + `apiHandler("get", "/api/v1/...", resolver)` / `apiOk(...)` / `apiProblem(...)` from `apps/web/src/test/msw.ts` (typed on the OpenAPI contract, unhandled requests fail).
  - E2E (Playwright + axe, `apps/web/e2e`): Postgres up (`docker compose -f deploy/compose.dev.yml up -d postgres`, empty database), backend built in Release, `pnpm --filter web build`, then once `pnpm --filter web e2e:prepare` (tenants `demo`/`beta`, client apps, users; secrets in the git-ignored `e2e/.env.e2e`) and `pnpm --filter web e2e` (starts API and `next start`; the global setup resets the passwords through auxctl, so it can run again). Every visited page runs `expectAccessible`; find controls by the translated text `t("key")` (IT bundle). With a preinstalled Chromium set `E2E_CHROMIUM_PATH`; CI job `e2e`.
  - i18n (`apps/web/src/i18n`, next-intl without locale routing): language from cookie `aux_lang` → `Accept-Language` → tenant default; tenant bundle from `GET /i18n/{lang}` (ETag, cached), static fallback `apps/web/messages/{en,it}.json` generated from the backend seeds with `pnpm --filter web i18n:sync` (a test fails when stale); use `useTranslations()` / `getTranslations()` with the full key (`t("nav.cases")`), never hard-coded text.
  - Routes: tenant app `app/[tenant]/(public)/…` (login, forgot-password, reset-password, activate, password-expired) and `app/[tenant]/(app)/…` (signed-in, `AppShell` with navigation from `/me/navigation`); links with `tenantHref(tenant, route)`, redirects after sign-in through `safeNextPath`; features in `src/features/<module>/`.
  - Tenant administration (S-01): console API `/api/v1/platform/tenants…` (`IPlatformTenantManager`, `IPlatformConsoleQueryService`), creation answers 202 and the Worker provisions (`ProvisionTenantCommand` → `TenantProvisioningWorkflow`, needs `Provisioning:AdminConnectionString`); first Administrator through the technical endpoints `/api/v1/administrators` (`Identity.Public.ITenantAdministratorManager`), invited by e-mail only; console pages `features/platform/components/tenant/*` with hooks in `features/platform/tenant-api.ts`.
  - Console routes: `app/platform/(public)/{login,activate}` and `app/platform/(console)/…` (signed-in, `ConsoleShell` + tenant selector; `loadConsole()` in `features/platform/server.ts`); the selected tenant is the slug in `/platform/tenants/{slug}/…` (`tenantConsoleHref`, `switchConsoleTenant`); technical endpoints of that tenant from the browser with `createBffClient("platform", { tenant })`. Both shells share `components/shell/shell-frame.tsx`.
  - UI kit (`apps/web/src/components`): server-side `DataTable` + `useTableState` (page/pageSize/sort/`filter[...]` in the URL via nuqs; `applyLayout`, `customFieldColumns` in `table-model.ts`), forms with `useZodForm` + `FormField` + `applyApiErrors` (zod messages are translation keys), `Combobox`, `useConfirm()`, `useNotify()` (sonner); reference page `app/[tenant]/(app)/login-audit`.
  - BFF (`apps/web/src/lib/bff`, ARCHITECTURE §14): the browser never sees tokens; tenant app `/api/auth/*` + `/api/bff/[...path]`, console `/api/platform-auth/*` + `/api/platform-bff/[...path]` (send `X-Tenant` for a tenant's technical endpoints); mutating calls need `X-Requested-With: auxilia`; Server Components call the API with `serverApi()` (`lib/api/server.ts`), Client Components with React Query + `createBffClient(area)` (`lib/api/client.ts`, typed from the OpenAPI contract) and `unwrap()`; errors are `ApiError` (`@auxilia/api-client`: `errorCode`, `traceId`, `fieldErrors`, `messageKey`) shown with `ApiErrorAlert`; configuration in `apps/web/.env.example` (client apps from `auxctl clients add`); CSP nonce in `src/proxy.ts`.
- CI (`.github/workflows/ci.yml`): backend, frontend, gitleaks CLI, osv-scanner CLI; license allowlist and per-package exceptions in `.github/` (ADR 0011).
